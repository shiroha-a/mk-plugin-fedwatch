# mk-plugin-fedwatch

[mk-go](https://github.com/shiroha-a/mk) のサーバープラグイン。連合先の状態を定期的に記録し、管理画面で「いつから落ちているか」を見られるようにする。

> **本体の 2.0 以降 (develop ではモジュールパスを変えたコミットの後) が要る。** 本体の Go のモジュールパスが `github.com/elythia-network/elythia` に変わった版に合わせてある。それより前の本体には、タグ `pre-elythia` の版を使う。

```
コントロールパネル → 連合
┌────────────────────────────────────────────────────┐
│ ▸ 連合の健康状態                    27 / 応答なし 1  │ ← 既定はこの 1 行
└────────────────────────────────────────────────────┘
   ↓ クリックで開く
┌────────────────────────────────────────────────────┐
│    27        1         0         0                  │
│  連合中    応答なし   停止中   ブロック              │
│                                                     │
│ ▸ 応答していない相手 (1)                            │
│    example.social  misskey 2026.6.0  フォロー 12    │
│                                       2日前から      │
│ ▸ 最近の変化                                        │
│    ● example.social  応答しなくなった          2日前 │
│    ○ third.example   バージョンが変わった      1日前 │
│                      2026.6.0 → 2026.7.0            │
│                                                     │
│ 最終取り込み: 12分前              [今すぐ取り込む]   │
└────────────────────────────────────────────────────┘
   ─────────────────────────────────────────
   [ホスト検索]  ← 本体の既存 UI
```

**独立したページは作らない。** 連合の状態を見に来るのはこのページなので、別の場所にもう 1 枚あると導線が分かれる。畳んだままでも要約が見えるようにしてある。

インスタンス情報のページには、その相手の**応答率**が 1 行で出る。

```
インスタンス情報 → example.social
  応答率  93.4%  過去30日  障害 4 回
```

## 数えるのは「連合中」だけ

一度でも接触すれば記録は残るので、観測している相手をすべて数えると**大半が「昔どこかから 1 通届いただけ」の相手**になる。落ちて困るのはやり取りが続いている相手だけなので、本体の `federating` と同じ定義（`followingCount > 0 OR followersCount > 0`）で絞って数える。

**記録そのものは全件残す。** 連合は切れたり戻ったりするので、絞るのは表示のときだけにしている。

## 本体の `/instances` と何が違うのか

本体は**今の状態**しか持たない。「落ちている」ことは分かるが、いつからなのかは分からない。運用で知りたいのはたいてい後者で、

- 昨日から落ちている相手なのか、さっき落ちたばかりなのか
- 落ちたり戻ったりを繰り返しているのか
- **こちらがフォローしている人がいる相手なのか**（実害の大きさ）

が分かると対応を決められる。このプラグインは本体の API を定期的に読んで**状態が変わった時だけ**記録し、その履歴を出す。

**外部には一切出ない。** 見るのは自分のインスタンスの API だけなので、相手のサーバーに負荷をかけない。

## 導入

```bash
# mk-go のリポジトリルートで
cd plugins
git clone https://github.com/shiroha-a/mk-plugin-fedwatch fedwatch
cd ..

make build && make uds-frontend-build && make uds-up
```

**コントロールパネル → 連合**を開く。ページの先頭に「連合の健康状態」が畳まれた状態で出る。

初回は空なので、開いて「今すぐ取り込む」を押すか、毎時 7 分の自動実行を待つ。

> **mk-go 2026.7.0 以降が要る。** 描画先の slot（`admin:federation` / `admin:instance-info`）は mk-go #2543 / #2545 で入ったもので、それより前のバージョンでは何も表示されない。

## 設定

省略できる。既定で動く。

```yaml
# .config/default.yml
plugins:
  fedwatch:
    enabled: true
    keepDays: 90        # 出来事を保持する日数
    pageSize: 100       # 1 回の API 呼び出しで取る件数 (本体の上限が 100)
    maxInstances: 5000  # 1 回の走査で見る上限
```

## 記録するもの

| 出来事 | いつ記録するか |
|---|---|
| `down` / `up` | 応答状態が変わったとき |
| `suspended` / `unsuspended` | 停止状態が変わったとき |
| `blocked` / `unblocked` | ブロック状態が変わったとき |
| `version` | ソフトウェアのバージョンが変わったとき |
| `appeared` | 初めて観測したとき |

**毎回の観測を全部残さない。** 連合先が数千あるインスタンスで 1 時間ごとに全件を積むと、1 年で数千万行になる。知りたいのは「変わった瞬間」なので、前回と違うときだけ 1 行足す。

## 応答率の出し方

本体は配送に失敗し続けると `isNotResponding` を立てるので、**その状態だった時間の割合**を出せば「どれだけ届かなかったか」の目安になる。

記録しているのは状態が変わった瞬間だけなので、期間の開始時点でどちらだったかは記録に無い。そこで**今の状態から逆向きに遡る**。`down` の出来事に当たれば「その前は応答していた」、`up` なら「その前は落ちていた」と分かるので、期間の頭まで確実に辿れる。期間より前の記録を読まずに済むのも利点で、何年ぶんの履歴があっても見るのは期間内の数件だけになる。

気をつけている点:

- **観測開始より前は測らない。** 遡って 100% と主張すると、入れたばかりのインスタンスで全部 100% に見える。実際に測れた日数を必ず添えて出す（「30 日で 100%」と「2 時間で 100%」は意味が違う）
- **今も落ちている分を数える。** 最後の `down` から現在までは `up` がまだ来ていないので、出来事だけ見ていると抜ける
- **期間より前から落ちていた場合を拾う。** その `down` は期間外にあるので、出来事が 1 つも無いまま「今落ちている」なら期間中ずっと落ちていたと見る
- **切り上げない。** 落ちていたのに 100% と出す方が困るので、下に丸める

## 権限

すべての API を `IsModerator()` で守っている。管理画面に出しただけでは API は誰でも叩けるので、表示の制御とは別に必ず弾く。

## 開発

```bash
cd plugins/fedwatch && go test ./...
```

DB は実 PostgreSQL を使う（`TEST_DB_*` 環境変数）。本体の API は差し替えるので外部には出ない。

### 設計上の注意

- **初回観測で `down` を立てない。** 立てると導入直後に「今日 100 件落ちた」と出て、履歴として読めなくなる。落ちている事実は現在の状態から分かるので、出来事としては `appeared` だけを残す
- **状態が変わっていないのに `state_since` を進めない。** 進めると「いつから落ちているか」が毎回 now() になって意味を失う
- **バージョンが空から埋まっただけのときは `version` を出さない。** 初回観測の副作用であって、更新ではない
- **`host` は必ずプレースホルダで渡す。** 管理者しか叩けない口でも、文字列連結で組むと SQL を注入できてしまう
- **`max()` は行が無くても NULL を返す**（`ErrNoRows` にはならない）。`time.Time` に直接 Scan すると導入直後に必ず失敗する
